## Questions

### Mission 0. What do find and union do, and what makes them fast in your code?

The `find` method finds the representative of a set. The `union` method joins two different sets. My implementation uses path compression and union by size to make these operations efficient.

### Mission 1. Why is Broken always R*C - 1, and Kept always (R-1)*(C-1)?

My maze has 8 rows and 11 columns, so it contains 88 cells. To connect all cells without cycles, we need 88 - 1 = 87 broken walls. There are 157 walls in total, so 157 - 87 = 70 walls are kept. For a rectangular grid, the number of kept walls is (R-1)*(C-1).

### Mission 2. What are your MST costs from Kruskal and Prim, and why are they equal?

The MST cost from Kruskal is 26068, and the MST cost from Prim is also 26068. Both algorithms find a minimum spanning tree, so they produce the same minimum total cost. However, they use different methods to select edges.

### Mission 3. Why is there exactly one path between two cells? How did you avoid a stack overflow on a huge maze?

The maze is connected and has no cycles, so it forms a tree. A tree has exactly one path between any two cells. I used iterative DFS with an explicit array stack instead of recursive DFS. This avoids using the program call stack for every step and reduces the risk of a stack overflow on a large maze.

### Mission 4. Why does the second pass of Kosaraju use the reversed graph? Why do the slides have no cycle exactly when Zones equals the number of cells?

Kosaraju's algorithm uses the reversed graph in its second pass to identify strongly connected components in the correct order. If every cell is its own strongly connected component, there are no cycles involving different cells. Therefore, the number of zones equals the number of cells when the slide graph has no cycles.

### Mission 5. Why is it enough to process the zones in the order of their numbers? What does this pass cost?

The zone graph is a directed acyclic graph (DAG), and the zone numbers follow a topological order. This allows the algorithm to process zones in order without using a priority queue. In my implementation, the route calculation takes O(m + z²) time and O(z²) space, where m is the number of slides and z is the number of zones.

## Complexity Analysis

Here, n is the number of cells, m is the number of walls or slides, and z is the number of zones.

| Algorithm               | Time Complexity                 | Space Complexity | Explanation                                   |
| ----------------------- | ------------------------------- | ---------------- | --------------------------------------------- |
| DSU find and union      | O(α(n)) amortized per operation | O(n)             | Uses path compression and union by size       |
| Kruskal                 | O(m log m)                      | O(n + m)         | Sorts edges by cost                           |
| Prim                    | O(m log m)                      | O(n + m)         | Uses a priority queue and adjacency list      |
| DFS                     | O(n + m)                        | O(n + m)         | Uses iterative depth-first search             |
| Kosaraju                | O(n + m)                        | O(n + m)         | Uses two DFS passes                           |
| Route in the zone graph | O(m + z²)                       | O(z²)            | Uses a zone cost matrix and topological order |
